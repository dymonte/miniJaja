MiniJaja - Memory & Execution Concepts

This document explains how MiniJaja manages memory during program execution — focusing on the execution stack, symbol table, and heap with garbage collection.

1. Example Program

class C { int x = 0; bool b = true; int t[4]; int fct(int max) { int y = 5; while (max > 0) { y += max; max = max - 1; }; return y; }; void result(int z) { write("x = "); writeln(x); }; main { if (b) { x = fct(x); } else { x = 0; }; result(x); } }

2. Execution Stack

The execution stack is a memory area used to store temporary information created during program execution.

Role Stores local variables, parameters, and return information for functions.
Scope Each time a method is called, a new “stack frame” is created.
Lifetime Variables are automatically destroyed when the method finishes.

Example:

x = 0; b = true; → main() starts → fct(x) is called → new stack frame created y = 5 max = 0 → returns y → frame destroyed

Think of the stack as a pile of sheets. Each function call adds a new sheet containing its variables and results. When the function ends, that sheet is removed.

3. Symbol Table

The symbol table (or data dictionary) acts like a dictionary that connects variable names to their information:

  • Identifier name (e.g., x, b)
  • Type (int, bool, etc.)
  • Kind (variable, constant, method)
  • Memory address (where it’s stored)
Identifier Type Category Address
x int variable 0x001
b bool variable 0x002
t int[4] array 0x003
fct method function 0x010

This table allows the interpreter to find variable information and manage their scope efficiently.

4. Heap Memory

The heap is a memory zone used to store data that can grow dynamically, such as arrays or objects created during execution.

In our example, the array int t[4] is allocated in the heap. The stack only holds a reference (address) to it.

Stack: ├─ x = 0 ├─ b = true └─ t → (address 0x200) Heap: [0x200] = [0, 0, 0, 0] ← content of array t[4]

5. Garbage Collector

The garbage collector automatically manages memory in the heap by freeing blocks that are no longer used.

Steps:

  1. Find objects that are no longer referenced by the program.
  2. Release (or “collect”) their memory.
  3. Optionally reorganize memory (merge adjacent free blocks).

Common strategies:

  • Simple release: the memory block is freed but not reused efficiently.
  • Coalescing: adjacent free blocks are merged into one larger block.
  • Reconstruction: memory is reorganized to optimize space usage.
Without garbage collection, unused objects would accumulate and eventually cause the program to run out of memory.

6. Stack vs Heap Comparison

Aspect Stack Heap
Purpose Stores local variables and function calls Stores dynamic data (arrays, objects)
Managed by Automatically by program execution Garbage Collector
Lifetime Until the function ends Until the object is no longer referenced
Access speed Very fast Fast

7. Execution Flow Summary

1. Class C is loaded 2. Variables (x, b, t) are initialized 3. main() executes 4. if (b) → true → call fct(x) → new stack frame: (max=0, y=5) → while (max>0) skipped → return 5 5. x = 5 6. result(x) → prints "x = 5"
